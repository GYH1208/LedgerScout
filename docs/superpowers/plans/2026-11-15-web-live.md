# Web Live Acceptance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Run the approved conversation UI against the existing real Runtime and verify source-backed results.

**Architecture:** A loopback HTTP adapter in `packages/web-server`, using the root tsx runner, exposes bounded job/session and evidence DTOs. A separate LiveApp shares visual primitives with the demo but never uses demonstration facts. Vite proxies /api; a local launcher starts both services.

**Tech Stack:** Existing Node >=22.19.0, TypeScript, React/Vite, node:test and Playwright. No new provider SDK or credential system.

**Spec:** `docs/superpowers/specs/2026-11-15-web-live-design.md`

## Global Constraints

- Only loopback access; no secret or arbitrary disk path in public responses.
- Real mode is explicit and has no sample fallback.
- Existing budgets, precision, evidence completeness and resume semantics remain authoritative.

## Review Focus

- Cross-origin requests cannot spend provider budgets or read local evidence.
- Invalid IDs and requests cannot access another run or cause arbitrary filesystem reads.
- Cancellation/busy/polling errors cannot silently produce a fabricated completion or stale result.
- No API key, transport URL or local directory reaches browser responses.
- Real evidence pagination is bounded and amounts retain original precision.
