# ENS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement task-by-task.

**Goal:** Accept ENS names as explicit research targets with fixed-block, auditable forward resolution.
**Architecture:** Deterministic normalization and fixed UniversalResolver eth_call, separate immutable ENS evidence, runtime pre-resolution authorization, durable session selection/checkpoint references.
**Tech Stack:** Existing Node24/TypeScript/Alchemy plus pinned ENS normalization and Keccak utilities.
**Spec:** docs/superpowers/specs/2026-11-12-ens-design.md

## Global constraints
- User explicitly requested directly implement/continue; inline on feat/ens-resolution; no additional approval gate/worktree.
- Preserve8model/12tool/32HTTP/120s caps, cancellation, exact amounts and date semantics.
- No chain writes, gateway fetches or arbitrary model-controlled eth_call.

## Review focus
- A failed/invalid name must never fall back to an old session address.
- Only verified current mappings can authorize new address tools.
- Recovery freezes successful mapping, validates evidence hash, and retains budgets.
- Reloading a session refreshes selected names but explicit historical evidence stays historical.
- Malformed ABI/Unicode/input boundaries cannot silently resolve a different target.
