# ERC20 Balance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Query exact balances for explicitly selected ERC20 contracts at a fixed Ethereum block.
**Architecture:** Fixed ABI reads through existing transport; query evidence and deterministic facts; separate holder/contract selection and checkpoint authorization.
**Tech Stack:** Existing Node/TypeScript/Pi/Alchemy, no new dependency.
**Spec:** docs/superpowers/specs/2026-11-12-erc20-balance-design.md

## Global Constraints
- Inline on feat/erc20-balance, user opted for direct execution, no extra approval gate/worktree.
- Integration requires explicit user instruction; received on 2026-11-13 for commit, merge and push.
- Preserve 8 model / 12 tool / 32 HTTP / 120-second limits and existing date/ENS/recovery rules.
- Only explicit contracts, fixed-block balanceOf/decimals; missing decimals means raw units, never guessed precision.

## Review Focus
- Contract addresses cannot accidentally become holders or authorize arbitrary holders.
- Symbol-only and invalid explicit targets cannot reuse stale contract selection.
- A decimals failure cannot erase valid raw balance or claim a formatted zero.
- Evidence/cache/resume must distinguish contracts and freeze original snapshot.
- Extra tool schemas must stay within current model-context limits.
