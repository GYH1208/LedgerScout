# Token 用量与上下文压缩

用户授权自主推进第一阶段；沿用 TypeScript、Pi 和 DeepSeek，在当前项目分支实施。

## 目标与方案

保留完整最近对话，以持久化摘要承接较旧对话，减少多轮研究时的上下文丢失。继续以查询证据而非摘要提供精确事实。

考虑三种方式：只裁剪最简单但会丢失意图；每轮总结会增加延迟和调用成本；接近容量时总结旧轮次兼顾两者，采用第三种。暂不增加跨会话记忆、自动续跑或供应商 tokenizer 下载依赖。

## 约束

- Token 分为请求前保守估算和供应商返回的实际用量。估算包含消息、工具定义及协议余量，明确标为 estimated；不声称本地精确复现 DeepSeek 聊天模板。实际用量按请求累计，缺失或失败请求计入 unknownRequests，不伪装为零。
- 默认上下文容量 12000 Token，预留 2000 输出 Token；原有 24000 字节硬上限保留。工具定义计入两个容量检查。限制只允许缩小。
- 超过可用输入容量 80% 或字节容量 80%，且有超过两个完整历史轮次时，尝试一次摘要；最近两个历史轮次及当前输入不进入摘要。
- 摘要使用同一模型调用入口，计入每轮最多 8 次请求、30 秒单次超时、120 秒整轮时限。至少保留两次请求供任务执行；摘要不开放工具，不进行修正重试。
- 摘要仅保存简短研究意图与未完成事项，最长 2000 字符、6000 UTF-8 字节。旧摘要与完整源轮次作为不可信数据；摘要放在低权限消息中，不成为系统指令、地址授权或事实证据。
- 查询 ID、地址、范围、取得时间、状态与完整性另由程序生成受限索引。索引仅包含本轮允许使用的证据；刷新请求不能从旧摘要获得事实。
- 摘要成功后替换对应历史前缀；失败或输入太大时降级完整轮次裁剪，记录原因。当前轮及工具调用配对不拆散，仍超限则明确失败。
- 会话可选 summary 字段兼容现有 version 1 文件；原始对话仍保留在各运行日志。摘要失败不更新摘要状态，取消继续走原有终态。

## 验收

离线测试覆盖中英文/工具 Schema 容量、当前轮保护、摘要持久化、失败降级、共享预算、取消、未知用量及旧证据不冒充新结果；运行全套测试与类型检查。真实模型不作为本轮自动验收前提。
