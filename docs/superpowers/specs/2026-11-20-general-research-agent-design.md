# LedgerScout 通用研究 Agent 迭代方案

日期：2026-11-20。状态：推荐设计草案；用户请求出方案，本轮不实施。用户确认的能力范围为：联网查资料、读取本地文件、分析数据、生成报告。

## 1. 产品目标与范围

将 LedgerScout 从 Ethereum 专用问答助手迭代为本地单用户的通用研究工作台。用户给出研究目标与材料后，Agent 在有界的流程中收集资料、整理证据、进行计算、形成结论，并交付可追溯报告。

首版支持的任务示例：

- 查找某个行业/产品的公开资料，比较多个对象并整理出处。
- 对用户选择的 PDF/文本材料进行摘要、比较、提取要点与冲突检查。
- 对 CSV/XLSX 做筛选、分组、汇总、趋势比较，生成图表并解释计算口径。
- 把网络来源、本地文档和表格结果组合成一份报告，保留缺口与不确定性。
- 继续调用现有 Ethereum 研究能力；美股沿用已保存的业务范围，在通用基础能力之后接入。

首版包含任务目录内的报告/图表/数据导出。任意Shell、通用代码执行、桌面与登录态浏览器自动化、交易下单、消息发送、无人值守后台执行、通用多Agent调度不属于本轮范围。数据分析由受限的结构化计算工具提供，不向模型开放整机命令执行权限。

## 2. 当前项目依据

以当前提交 `d6e9120` 为基础检查：

- `engine/pi.ts` 已把 Pi 与内部消息、工具、模型调用接口隔离，可以复用。
- `types.ts` 已有基础工具Schema、取消信号、模型请求接口与供应商用量。
- 运行预算、日志、Token统计、上下文压缩、手动取消/恢复、SQLite历史与Web工作台已有实现。
- `runtime.ts` 同时处理地址/ENS/合约授权、日期区块、领域工具、答案校验、预算与持久化，不能直接作为领域无关内核。
- `SessionStore`、`CheckpointStore`、`RunResult`、`publicQuery` 与Web历史校验依赖链上 `QueryResult`、address/network/range。通用文件和网页不能通过伪造地址字段接入。
- Web当前要求DeepSeek、Alchemy、Etherscan全部就绪。通用研究必须按实际能力检查配置。
- 11月15日小样本实测在旧8次模型预算下出现资金流无进展重复调用，以及合约后的中文句号解析问题；之后仅扩大预算至15次，未进行同组性能重测。不能宣称扩大预算已经修复循环问题。

## 3. 实现路线比较

| 路线 | 收益 | 代价 | 判断 |
|---|---|---|---|
| 保留领域专用Runtime，通过顶层路由给每个新领域单独增加Agent | 最快做出第二个垂直功能，改动范围较小 | 预算、记忆、证据、恢复与工具选择逻辑容易重复；混合材料任务仍缺统一上下文 | 可作为过渡兼容层 |
| 通用研究内核＋能力模块＋领域适配器 | Web、本地文件、表格、链上与后续股票能共用任务/证据/交付机制 | 需先解耦协议，补迁移与链上回归，首次投入较多 | 推荐路线 |

本稿采用第二条作为推荐，保留旧入口进行渐进迁移。A阶段通过兼容桥继续路由到原Ethereum运行器，不要求当时迁完全部链上业务；D阶段再完成标准化能力迁移。在迁移完成前，链上任务与通用任务各自有一个实际运行器，不能外层再启动模型循环或借嵌套调用重置预算；通用研究里混合链上查询的承诺在D阶段验收。沿用Node/TypeScript、当前锁定的Pi版本、DeepSeek和SQLite；本阶段不迁移框架、数据库或模型供应商。架构选择与下面的默认范围属于方案建议，尚非用户已确认的实施授权。

## 4. 核心结构

初期在现有包内分层，边界稳定后再判断是否需要拆包，避免仅为目录整齐增加服务数量。

| 层 | 职责 | 不承担的内容 |
|---|---|---|
| 通用Runtime | 任务状态、有限计划、模型/工具调度、预算、超时、取消、检查点、事件、结果校验 | 地址解析、财务公式、网页正文提取等业务 |
| 能力注册与策略 | 按任务选择工具/技能、检查配置与资源授权、声明输入输出Schema及分页上限 | 通过prompt自行授予权限 |
| 证据与产物服务 | 不可变来源快照、定位、哈希、计算血缘、报告/图表文件及下载 | 把模型记忆当成当前事实 |
| 工作区与历史 | 会话、任务、材料、摘要、检索、报告和资源授权 | 自动读取用户未选择的本地文件 |
| 领域适配器 | Ethereum与未来美股的目标校验、专属计算、来源/答案校验 | 复制整套通用执行内核 |

`runtime.ts`逐步变为兼容入口；领域逻辑迁入Ethereum适配器，Pi执行器尽量保持。模型配置从链上配置独立；工具能力未配置时只禁用该能力。

### 4.1 通用协议

引入版本化的 `Task / Source / Evidence / Analysis / Artifact / Capability`，而非直接无限扩展链上查询类型：

- Task：目标、输入材料、允许的能力和资源、验收要求、步骤状态、累计预算、完成/部分/等待输入/失败/取消等状态。
- Source：网页、用户输入、本地文档、数据表或领域API的稳定身份；包含来源类型、标题、发布时间（已知时）、获取时间、内容哈希和版本。发布时间与获取时间分开。
- Evidence：Source中的可定位片段，如网页段落、PDF页/段落、表格sheet/行列与领域queryId。
- Analysis：输入快照、计算操作与参数、缺失处理、单位/时区/精度、结果及可重放计算描述。派生结论与原始材料分开。
- Artifact：由任务生成的报告、表格与图表，带版本、哈希、媒体类型、生成任务和证据引用。对外使用ID，内部路径不作为任意文件访问入口。
- Capability：配置需求、工具集合、参数和结果Schema、只读或任务产物写入、资源范围、结果大小/游标/超时/成本、收尾条件和领域验证器。

链上查询保留原格式与严格数值验证，以适配器提供通用Evidence视图。旧字段不被强行改成泛型字典。通用任务可以组合多种材料；旧Ethereum会话的地址授权和证据使用边界保持原语义，不因接入新能力而扩大。

### 4.2 执行与收敛

推荐流程为：理解目标与材料 → 生成短计划 → 获取所需来源 → 计算/比较 → 校验关键事实 → 生成报告与缺口。简单任务直接执行，复杂任务使用同一Agent的阶段状态；不强制每阶段都调用一次模型。

- 每阶段只加载用得到的少量工具；先列材料/摘要，确有需要再读取细节。选择器可确定性判断常见输入，存在歧义时由模型在已授权能力中选择。
- 统一工具摘要、记录数、`nextCursor/hasMore`与实际分页上限；Schema和执行层不得表达不同的数量限制。
- 相同只读签名优先复用缓存。同一来源、参数、游标重复返回同内容视为无进展；默认第2次无进展读取后停止此路径，要求改变策略或收尾，具体阈值可配置并经回归验证。
- 预留收尾预算。达到限制时输出已验证结果和未完成部分，不能无限读证据直到没有生成答案的余量。子步骤共享父任务计数，恢复也不重置预算。
- 当前默认15次模型请求、35秒单次模型超时、300秒整轮、12次工具调用、32次数据HTTP尝试先作为基线保留。研究深度影响计划与来源数量；后续预算配置改变必须显示在任务记录中，不隐式扩大。
- 验证分层：程序检查引用存在/定位、计算与数值、文件生成和状态；语义支持、来源冲突处理与研究充分性另外评估。引用存在不等于结论得到来源支持。

## 5. 首版通用能力

### 5.1 联网研究

- 提供搜索、读取公网页面、来源内检索与证据片段读取。搜索适配器优先验证Tavily基本搜索；网页读取采用受限后端获取，必要时再评估单独的提取接口。
- Tavily文档在2026-11-20列出每月1000免费credits，basic搜索每次1credit。作为低成本个人试用候选，不承诺能覆盖任意使用量。应用需自己的搜索凭据，开发环境内置联网工具不是产品依赖。免费额度也不表示DeepSeek推理免费。
- 搜索摘要只用于发现来源。关键事实优先阅读原始/官方页面，记录真实读取范围；正文不可得时明确标记仅有摘要，不装作读过全文。
- 日期限定、来源去重、同一来源的转载识别与冲突提示纳入结果。确有多方证据需要时寻找独立来源，不能机械把任意两个转载当交叉验证。
- 获取器校验公网URL、DNS与重定向，限制响应大小/类型、时间与解析资源；本地/内网/元数据地址不可经网页工具读取。网页文字不能改变系统指令、资源授权或可用工具。
- 首版不自动登录、不访问付费墙、不全站爬取。限流/不可达时提供可取得内容与缺口，配置缺失不伪造搜索结果。

### 5.2 本地材料

- 用户选择上传文件或明确授权目录；首版优先UTF-8文本/Markdown、可提取文本的PDF、CSV/XLSX。DOCX列为后续解析器扩展，首版不承诺OCR识别扫描件。
- 导入时固定文件版本与哈希；段落、页码或sheet定位可重查。明确路径边界、文件/压缩展开大小与格式验证，处理损坏、密码保护、空文件、超大文件及符号链接。
- 本地材料不会自动整份发给模型：先生成目录与提取索引，再按任务读取有界片段。默认不把材料正文发送给搜索供应商；用户要求联网查找时，搜索查询仅使用完成任务所需的最少信息，涉及非公开原文或具体敏感标识时需显式授权。
- 可用SQLite索引文本做首版检索，先验证检索命中与段落定位，再根据长文/多文件任务评测决定是否引入向量检索。无需先建立向量数据库。

### 5.3 数据分析

- 读取字段类型、数据样本、行数、缺失、重复与时间范围，先展示当前数据理解和所用口径。
- 首版支持筛选、排序、分组、连接、汇总、比例、同比/环比与趋势；通过受限操作Schema执行，禁止任意eval或由模型生成的整机命令。
- 财务/金额保留必要精度和币种；禁止把缺失值当0，百分比必须明确分母，时间序列明确时区/频率/重采样。检测表连接放大与数据重复。
- 大表先做程序聚合，模型只读取数据质量摘要、计算表和必要样本。记录输入哈希及计算操作，输出CSV和可复现的分析描述。
- 图表由计算结果生成，默认SVG或独立HTML，包含单位、时间范围与来源。模型不能另造一份图表数字。

### 5.4 报告与追问

- 一份报告可结合多类材料，结构按任务选择：结论、证据、分析方法、冲突/限制、后续待查事项。
- 首版交付会话中的可读结果、可下载Markdown/HTML报告，以及关联CSV与图表。PDF/DOCX属于后续渲染适配；已有单次输出限制不被默默扩大，长报告按共享预算分节生成，超预算时交付明确的部分稿。
- 关键事实关联Evidence；所有程序计算能追到输入和公式。缺少依据的判断标明分析或假设，不能用格式化的引用掩盖证据缺失。
- 生成文件只允许进入任务输出目录，命名冲突生成新版本；不覆盖原始输入。HTML/Markdown外部内容按不可信数据转义，下载与预览使用受控ID和媒体类型。
- 追问复用原快照，标记材料日期；用户明确要求“最新/刷新”时再获取新材料，不把旧摘要视为新事实。

## 6. 记忆、任务和工作台

- 区分会话原文、任务工作状态、压缩摘要、证据库与可编辑偏好。偏好记录来源与生效范围；本阶段不把模型自行推断的人设写成长期记忆。
- SQLite继续保存会话/任务/材料/证据索引/产物元数据；大文件与不可变证据保存在本地文件。工作区控制数据共享范围，默认不跨会话检索用户材料。
- 先做材料和证据检索，再扩展长期个人记忆。删除入口说明会删除哪些原文、索引、派生报告与历史引用；历史报告遇来源已删除时明确说明，不悄悄换引用。
- 延续左侧会话/材料、中间任务与报告、右侧证据的已批准视觉。任务状态显示正在收集、分析、写报告，以及已完成和未完成步骤。支持搜索历史研究与下载产物。
- 本轮仅定义信息架构，实施阶段沿用现有视觉做具体页面，不在方案阶段生成新视觉稿。

## 7. 持久化与渐进迁移

1. 先用离线固定案例建立现有链上与恢复基线，抽出预算、事件、模型接口等领域无关原语。
2. 增加版本化通用任务/证据/产物协议与兼容读取；旧Ethereum会话、queryId、原始文件与哈希保持可读。
3. 现有Web入口继续工作；新增研究入口按配置显示可用能力。不要求研究用户配置Alchemy/Etherscan。
4. 旧链上检查点使用旧恢复器；通用检查点声明版本、能力/参数版本、材料版本和资源授权。只读步骤可复用证据，产物写入使用幂等ID；不对未知状态的步骤盲目重放。
5. SQLite增加新表/索引，通过显式版本化迁移。一致备份后迁移，失败保留原文件，原始证据和数据库一并恢复。

美股11月15日设计保留为业务能力范围，后续把其中证据/会话/Runtime改造替换为本通用协议；行情源、证券身份、财务口径与免费覆盖验证仍然需要独立完成。本次不因通用化而视为已实现美股模块。

## 8. 交付阶段与验收

| 阶段 | 主要交付 | 离开该阶段的条件 |
|---|---|---|
| A 通用底座与执行质量 | 协议、能力注册、配置隔离、收敛/收尾、旧数据兼容与Ethereum旧运行器兼容桥 | 无链上目标也能基于用户直接提供的文本完成摘要/比较任务；通用工具循环通过离线固定材料验证；原链上入口与旧恢复通过回归；不提前算作已有联网/文件能力 |
| B 联网＋文件研究闭环 | 搜索/网页、文本/PDF、证据索引、来源定位、短报告 | 网络与本地材料可混合引用；错误/扫描PDF/无法读全文等边界真实反映；重启和追问可用 |
| C 数据分析与完整交付 | CSV/XLSX、结构化计算、图表、Markdown/HTML报告与下载 | 计算可重放，数字一致；报告包含有效证据；任务状态与产物可持久恢复 |
| D 领域扩展与连接器 | 将Ethereum全部现有能力从兼容桥迁为标准能力模块，美股按既有设计接入，必要时增加MCP适配器 | 链上可与其他研究来源共同使用且共享任务预算；新能力通过注册及协议接入，核心不再新增硬编码领域分支；提供各领域独立验收 |

各阶段分别形成可用增量，B结束已有“读网页/文件→形成有来源短报告”的可用产品，C结束覆盖用户本次提出的完整能力组合。不会用空UI或伪造数据宣称某一阶段完成。

### 固定评测

- 建立24个版本化研究任务：8个联网、6个文件、6个表格、4个混合来源；另保留独立的链上/存储/恢复回归与失败边界测试。数据、问题、期望关键事实/计算、完整/部分成功判定在运行前确定。
- 每个任务检查：是否交付所需结果；关键数值是否与输入一致；引用是否真实且支持结论；缺失/冲突处理；复算一致；是否发生未授权资源访问、重复无进展调用和恢复重放。
- 固定评测集以至少90%的任务完成率为首轮目标，关键计算与来源定位必须通过；这是实现目标，不是当前成绩。声明Partial并不自动算成功，要按任务预先定义的最低交付标准判定。
- 记录模型/工具/HTTP次数、供应商Token、耗时分段、有效新证据数量、缓存命中、循环阻断、恢复复用及产物交付。外部网页变化与模型随机性独立记录；同模型、同预算、同输入比较改动前后结果，小样本不提供泛化p95结论。
- 报告中的引用结构可自动验，但对证据支持与推理质量安排人工抽查，不用一次模型自评代替正确性验证。真实有费用验收在实施阶段有界运行，不包含在普通测试。
