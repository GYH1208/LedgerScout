# 显式中断恢复

在用户要求合并到main后继续的授权下，采用TypeScript本地检查点，沿用Pi循环与现有只读数据服务。main已快进至f4ecdc6且91项测试和类型检查通过；后续在feat/run-resume实现。

## 选择

整轮重新查询简单但会丢失进度和快照；完整分页游标恢复需要扩展每种供应商分页协议；首版选模型/工具边界检查点，复用已完成工具，未完成的只读查询从第一页重试。没有跨进程任务调度或后台自动恢复。

## 行为与约束

- 新入口 `--session S --resume R`，不能同时提供新问题；普通打开会话仍只标记中断，不发起请求。API提供resumeRunId选项，必须有sessionId且input为空。
- 每次恢复创建新runId并记录resumeOf、运行链。原日志/证据保留；源检查点记录resumedBy，防止重复分叉，已恢复的源提示新runId。
- 原子检查点保存原输入、授权地址、模型请求上下文及响应、工具结果、查询证据引用与哈希、固定区块、累计调用数/用量、失败限制、修正标记及原运行限制。关键写盘完成后才发起新增模型/HTTP请求。
- 保存最后一轮模型请求；有已保存响应时在Pi边界重放该响应，已完成工具按调用ID返回保存结果且不重复扣费；待完成工具继续执行。查询缓存和同参数失败计数保留。未知/非法工具仍由Pi Schema拒绝。
- 查询快照一旦获得即先落检查点，恢复沿用固定区块；未取得快照时重新建立快照。完成结果按实际获取时间展示；明确恢复数据不是最新刷新。
- 模型8次、工具12次、HTTP32次和原先更小的限制沿运行链累计，不因恢复重置。记录实际活跃耗时；崩溃时对在途模型/工具保守扣除其超时额度，离线等待不计入活跃耗时。恢复不能扩充原限制。
- cancelled、failed及非终结性partial可显式恢复；正常完成、待用户补充、因分页上限得到的完整回答、预算耗尽均关闭检查点。缺少或损坏检查点、证据不一致、跨会话或路径穿越在网络前拒绝。
- 恢复仍受相同进程内会话锁保护；不承诺多进程并发。每个恢复源只消费一次；子检查点先保存、源链接后提交，源链接提交前不发新增请求。
- 旧版运行没有检查点，不推断日志重建；提示重新提问。检查点脱敏，不保存密钥、凭据或任意路径。

## 验收

真实Pi+模拟模型/HTTP测试：工具批次中取消后恢复，完成工具不重查、未完成查询固定快照；模型等待取消后恢复上下文；累计预算和用量、不扩权、证据损坏/已消费/已完成拒绝、正常打开不重放。覆盖原子写入失败与真实子进程退出后的恢复；运行全套与类型检查，独立审阅。
