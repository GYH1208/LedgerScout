# 单地址资金流分析

用户确认直接实现先前建议：按币种流入/流出/净流量、主要对手方、带证据与覆盖范围的研究摘要。按用户“直接做”的要求跳过额外设计问答，沿用 TypeScript/Pi/Alchemy 数据层。

## 架构选择

采用确定性本地聚合，基于 list_asset_transfers 的完整已取得记录，不对有限模型预览计算。模型负责工具选择与解释，金额和排名由程序生成。无需新供应商、价格接口、依赖或额外链上请求。相比由模型直接加总，此方案保证大整数精度和同币种排名；暂不提供法币估值、利润、身份归因或余额变化。

新增 chain-data/flows.ts 纯函数。新转账 query.json 内保存 flowAnalysis。分析工具 analyze_asset_flows(queryId) 读取既有转账证据，兼容旧查询时重新计算；read_query_evidence 可分页读取 flow_assets / flow_counterparties。统计与回答渲染都从原始记录确定性生成，不能信任模型另填数字。

## 计量口径

- Ethereum Mainnet，单地址、单个转账查询；不合并不同窗口或查询，沿用既有日期、快照、取消与预算。
- ETH 合并 external/internal，单位 wei，精度18；ERC20 以规范化合约地址为唯一币种身份，不能按符号合并。同合约符号差异只作为元数据。合约缺失时不参与币种金额汇总。
- 金额使用原始十六进制整数和 BigInt，所有序列化金额为十进制字符串。ERC20 精度缺失或冲突不产生精确显示金额；原始单位小计仍保留。浮点 approximateValue 不用于精确统计。
- 原始金额缺失/非法单列未计金额记录，已知小计标注不能代表完整金额。精度上限255，单个原始金额最多uint256，防止异常元数据无限放大计算。
- 按 id 去重；跨方向相同自转仅计一次，单列 self，不计入流入/流出净额与对手方排名。相同id存在不同核心内容时整条排除，明确记录冲突。
- 外部/内部ETH来自转账接口，普通交易列表不再加一次。不含gas/NFT/零值；净流量不等于利润或余额差。
- 每资产 incoming/outgoing/self 的记录数、已知原始单位金额、净已知金额、可用精度、格式化值、缺金额数和recordIds都保留。net=incoming−outgoing。
- 主要对手方按唯一转账记录数排序，平局按地址排序；未知to单独计数。每资产再给出已知流入/流出原始金额排名，最多5名，明确“已知金额排名”与缺失金额影响。
- 全部统计仅代表已取得样本。继承源查询每方向complete/stopReason和queryId；partial时不能称全窗口最大对手方或完整净额。

## 输出与证据

模型工具预览有界，最多前3个币种/对手方概览并按800字节目标裁剪，保留总分组数；分析请求的源查询预览只给概况。分页读取返回精简统计，最多5条且按大小裁剪，以实际返回条数和hasMore继续。完整派生报告和贡献recordIds保存在query.json，不改变源记录。
为支持多次明细读取，模型请求准备阶段将较早的资金流相关工具结果替换为queryId引用，保留完整工具配对与最新结果，按需可重读；不修改原始工具返回或源证据。资金流说明只注入相应请求，保持普通日期查询容量。
回答新增 flow_summary 与 counterparties 事实引用，只允许转账查询；程序重新计算事实。默认按记录数展示最多10币种、5个对手方；每币种同币种已知金额前3名，剩余条目明确提示可分页读取。
若用户要求资金流分析，最终合法回答必须包含相应转账证据的分析事实，避免仅返回计数冒充分析；失败降级也展示已有派生统计。
所有金额与对手方均可追溯到源queryId和recordIds。旧日期窗口权限与恢复证据哈希规则保持有效；分析工具只使用当前允许证据，不重置调用预算。
